# Normalisation — From `DowContext` JSON to MLP Input Tensor

This document explains, step by step, how a single closed `Position` from
`output/data.json` is transformed into the 77-element float tensor that
`GenericMLP.forward()` actually receives.

Worked examples throughout use the **first row of the training split** in the
current dataset — a real `PL=F` (Platinum futures) `LONG BREAKTHROUGH` trade
opened on `1997-12-29`. Every numeric value below can be cross-referenced
against [output/data_ingestion_template.json](../output/data_ingestion_template.json),
which is generated by [export_input_template.py](export_input_template.py).

---

## Section 1 — Why normalize at all

The trading universe spans 32 commodity-futures contracts whose price
magnitudes differ by orders of magnitude (Platinum at ~$365, ZW=F wheat at
~$5/bushel, ETH=F at ~$3000). Raw prices, slopes, and volumes from one ticker
would dwarf those from another, and the MLP would spend most of its capacity
learning ticker identity rather than market-state patterns.

The pipeline addresses this with three sequential stages:

1. **Extraction** — turn the heterogenous `DowContext` JSON into 77 floats,
   normalized so the same numeric scale carries the same meaning across every
   ticker (e.g. price distances become "ATR-multiples from purchase").
2. **Winsorization** — clip rare outliers so a single freak bar can't dominate
   the next stage's statistics.
3. **Standard scaling** — recenter every feature to zero mean and unit
   variance. After this step the MLP receives values that are roughly
   `O(1)`, which keeps gradient magnitudes well-behaved across all 77 input
   weights of the first hidden layer.

## Section 2 — Stage 1: Feature Extraction

Implemented in [neural_network.py:`extract_context_features`](neural_network.py#L210-L253).
Produces 76 floats per `entryContext`; the loader prepends `positionType` for a
total of **77**.

The full ordered name list lives in
[neural_network.py:`FEATURE_NAMES`](neural_network.py#L56-L72).

### 2.1 Position type (1 feature)

| Source | Transform | Example |
|---|---|---|
| `position.positionType` | `LONG → 1.0`, `SHORT → 0.0` | `"LONG"` → `1.0` |

This is the only feature taken from the top-level `Position` object rather
than from `entryContext`.

### 2.2 Price statistics (9 features)

[`_price_stats_features`](neural_network.py#L95-L117). Read from
`entryContext.priceStatistics`. The per-ticker scale of price is removed by
expressing every level in **ATR-multiples from `purchasePrice`** and every
slope in **per-bar return units** (slope ÷ window mean).

| Feature | Formula |
|---|---|
| `price_mean_atr`     | `(mean - purchasePrice) / atrValue` |
| `price_std_atr`      | `std / atrValue` |
| `price_min_atr`      | `(min - purchasePrice) / atrValue` |
| `price_max_atr`      | `(max - purchasePrice) / atrValue` |
| `price_slope_ret`    | `slope / mean` |
| `price_slopeSE_ret`  | `slopeSE / mean` |
| `price_slopeRSQ`     | passed through (already `[0, 1]`) |
| `price_slopeSig`     | `slopeSignificant ? 1.0 : 0.0` |
| `price_cov`          | `std / mean` (coefficient of variation) |

**Worked example (`price_mean_atr`, the second feature in the tensor):**

```
mean           = 368.135      (priceStatistics.mean over the lookback window)
purchasePrice  = 365.000
atrValue       =   7.055

(368.135 - 365.000) / 7.055   = 3.135 / 7.055   = 0.4444
```

So the MLP sees `0.4444` here instead of the raw price `368.135`. The same
"0.4444" would mean the same thing for ETH-USD or wheat — the scale is gone.

### 2.3 Volume statistics (9 features)

[`_volume_stats_features`](neural_network.py#L120-L142). Read from
`entryContext.volumeStatistics`. Raw volumes span many decades (corn vs.
crypto), so each level is `log1p`-transformed; slopes are normalized by the
window mean exactly like prices.

| Feature | Formula |
|---|---|
| `vol_log_mean` | `log1p(max(mean, 0))` |
| `vol_log_std`  | `log1p(max(std, 0))` |
| `vol_log_min`  | `log1p(max(min, 0))` |
| `vol_log_max`  | `log1p(max(max, 0))` |
| `vol_slope_frac`   | `slope / mean` |
| `vol_slopeSE_frac` | `slopeSE / mean` |
| `vol_slopeRSQ`     | passed through |
| `vol_slopeSig`     | `slopeSignificant ? 1.0 : 0.0` |
| `vol_cov`          | `std / mean` |

`log1p(x) = log(1 + x)` is used instead of `log(x)` so that zero/empty
volume bars (early in a ticker's history) yield zero rather than `-inf`.

### 2.4 MACD block (3 features)

Inline in [`extract_context_features`](neural_network.py#L233-L235). The two
indicator levels are normalized into per-bar return units by dividing by
`priceStatistics.mean`.

| Feature | Formula |
|---|---|
| `macd_ret`   | `macd / mean_price` |
| `signal_ret` | `signal / mean_price` |
| `macdReady`  | bool → 1.0/0.0 |

### 2.5 Trend (17 features)

[`_trend_features`](neural_network.py#L163-L175) +
[`_extremum_features`](neural_network.py#L145-L160). A trend is a sequence of
five extremums `e1 .. e5`. Their absolute bar indices are useless across
tickers, so each extremum is encoded relative to **`e1.date`** (the trend's own
anchor).

Layout: `[trend_ready, trend_type, e1×3, e2×3, e3×3, e4×3, e5×3]`

| Feature | Formula |
|---|---|
| `trend_ready` | bool → 1.0/0.0 |
| `trend_type`  | `UPTREND → 1.0`, `NONE → 0.0`, `DOWNTREND → -1.0` |
| `trend_eK_days`      | `(eK.date - e1.date).days` |
| `trend_eK_close_atr` | `(eK.close - purchasePrice) / atrValue` |
| `trend_eK_trough`    | `eK.isTrough ? 1.0 : 0.0` |

Missing extremums (`index == -1`) zero-fill all three of their slots — the MLP
sees a neutral signal rather than a meaningless `-purchasePrice/atr` distance
from a fictitious zero close.

**Worked example (`trend_e2_days`, index 28):**

```
e1.date = 1997-12-16
e2.date = 1997-12-18

(1997-12-18 - 1997-12-16).days = 2
```

### 2.6 TrendLine (6 features)

[`_trendline_features`](neural_network.py#L178-L207). A regression line fit to
the trend's extremums; the projected price at the current bar matters more
than the raw line coefficients.

| Feature | Formula |
|---|---|
| `tl_ready`         | bool → 1.0/0.0 |
| `tl_active`        | bool → 1.0/0.0 |
| `tl_slope_ret`     | `slope / mean_price` |
| `tl_intercept_atr` | `(intercept - purchasePrice) / atrValue` |
| `tl_dateDiff`      | passed through |
| `tl_proj_atr`      | `(purchasePrice - (intercept + slope*dateDiff)) / atrValue` |

When the trendline is not ready or not active, the four numeric features are
zeroed so a missing line reports a neutral signal.

### 2.7 DoubleTrend & DoubleTrendLine (17 + 6 features)

Identical shape to Trend / TrendLine, but anchored to `doubleAtrValue` and
the `doubleTrend.e1` date. Used to expose a slower-timescale trend regime to
the MLP simultaneously.

### 2.8 RSI (4 features)

| Feature | Formula |
|---|---|
| `rsi`             | `rsiValue` (raw — already `[0, 100]`) |
| `rsiReady`        | bool → 1.0/0.0 |
| `doubleRsi`       | `doubleRsiValue` (raw) |
| `doubleRsiReady`  | bool → 1.0/0.0 |

RSI is left untransformed because its native range is already bounded and
ticker-independent. Stage 3 (scaling) will recenter it.

### 2.9 ATR / volatility (5 features)

| Feature | Formula |
|---|---|
| `atr_ret`         | `atrValue / purchasePrice` |
| `atrReady`        | bool → 1.0/0.0 |
| `doubleAtr_ret`   | `doubleAtrValue / purchasePrice` |
| `doubleAtrReady`  | bool → 1.0/0.0 |
| `vol_ratio`       | `atrValue / doubleAtrValue` (volatility regime ratio; `0.0` when divisor too small) |

## Section 3 — Stage 2: Winsorization

Implemented in [neural_network.py:`_winsorize_fit` / `_winsorize_apply`](neural_network.py#L311-L319).

### Why

A single freak bar (a flash crash, a reporting error, a thinly-traded session
on a holiday) can produce an extracted feature value 50 standard deviations
out. Without clipping, that single sample dominates the mean and standard
deviation that Stage 3's `StandardScaler` will compute, distorting *every*
feature for *every* training row.

### How

For each feature `j` (column), bounds are fit from the **training split only**
at `[1%, 99%]` percentiles:

```python
winsor_lo[j] = np.percentile(X_train[:, j],  1.0)
winsor_hi[j] = np.percentile(X_train[:, j], 99.0)
```

Every split (train, val, test, and any inference data) is then clipped using
the **same** bounds:

```python
X[:, j] = np.clip(X[:, j], winsor_lo[j], winsor_hi[j])
```

Computing the bounds on train alone prevents validation/test outliers from
leaking information into the model.

### Worked example (`vol_ratio`, index 76)

The Platinum trade has `doubleAtrValue == 0.0`, so extraction returns
`0.0` (the `_safe_div` guard fires when the denominator is too small). But
the **training** distribution has a 1st-percentile floor of `0.0100` for this
feature — every other training row has at least some `vol_ratio` signal, so
the floor is well above zero. Result:

```
raw           = 0.0000
winsor_lo[76] = 0.0100
winsor_hi[76] = 1.5469

clip(0.0000, 0.0100, 1.5469) = 0.0100   ← clipped UP to the floor
```

This is the correct behaviour: an outlier that disagrees with 99% of training
data gets pulled toward the bulk of the distribution rather than dominating
Stage 3's statistics.

## Section 4 — Stage 3: Standard Scaling

Implemented in [neural_network.py:`normalise`](neural_network.py#L322-L361),
using `sklearn.preprocessing.StandardScaler`.

### Why

After winsorization, features still occupy wildly different ranges:
`positionType ∈ {0, 1}`, `rsi ∈ [0, 100]`, `vol_log_mean ≈ 22`,
`price_mean_atr ≈ ±5`. Feeding values that span three orders of magnitude
into the same first-layer matrix multiply means the gradient updates for
those weights would also span three orders of magnitude — training is much
harder.

`StandardScaler` recenters each column to zero mean and rescales to unit
variance, so every feature contributes on the same scale to the first
hidden layer.

### How

The scaler is **fit on the post-winsorization training matrix**:

```python
mean_[j]  = X_train_winsorized[:, j].mean()
scale_[j] = X_train_winsorized[:, j].std()
```

and applied to all splits:

```python
value_scaled = (value_winsorized - mean_[j]) / scale_[j]
```

The fitted `mean_` and `scale_` arrays (along with the winsorize bounds and
scaler kind) are pickled to [scaler.pkl](scaler.pkl) so inference replays the
exact same transformation deterministically.

### Worked example (`price_mean_atr`, index 1)

Continuing the same Platinum trade:

```
winsorized   = 0.4444     (Stage 2 output, unchanged because it was inside [-9.45, 4.05])
mean_[1]     = -1.0737    (training-split column mean of price_mean_atr)
scale_[1]    =  2.3202    (training-split column std)

(0.4444 - (-1.0737)) / 2.3202   = 1.5181 / 2.3202   = 0.6543
```

`0.6543` is the literal value the MLP sees at index `1` of its 77-element
input tensor. Cross-check: this matches `mlp_input.values[1].value` in
[output/data_ingestion_template.json](../output/data_ingestion_template.json).

## Section 5 — Putting It All Together

For one feature (`price_mean_atr`), one trade (`PL=F` on 1997-12-29):

```
RAW JSON         priceStatistics.mean = 368.135      (priceStatistics.mean over the lookback window)
                 purchasePrice        = 365.000
                 atrValue             =   7.055

EXTRACTION       (368.135 - 365.000) / 7.055         = 0.4444
WINSORIZATION    clip(0.4444, lo=-9.4549, hi=4.0524) = 0.4444   (no clip — within bounds)
STANDARD SCALE   (0.4444 - (-1.0737)) / 2.3202      = 0.6543

MLP RECEIVES     0.6543   ← element 1 of input tensor (float32)
```

Repeated 77 times, once per feature, and you have the complete tensor handed
to `GenericMLP.forward()`. The exported template
[output/data_ingestion_template.json](../output/data_ingestion_template.json)
is exactly this — for one real training row, with all four columns
(`raw`, `winsorized`, `value`, plus the per-feature `winsor_lo/hi/scaler_mean/std`)
laid out side-by-side for inspection.

## Section 6 — Reproducing on New Data

For inference (or any audit), use the saved bundle from `scaler.pkl`. **Never
refit** — the train-split statistics are what the model was calibrated against;
a refit on different data introduces silent input drift. The canonical replay
function lives in
[feature_diagnostics.py:`apply_scaler_bundle`](feature_diagnostics.py#L46-L56):

```python
def apply_scaler_bundle(X_train, X_val, X_test, bundle):
    lo, hi = bundle.get("winsor_lo"), bundle.get("winsor_hi")
    if lo is not None and hi is not None:
        X_train = _winsorize_apply(X_train, lo, hi)
        X_val   = _winsorize_apply(X_val,   lo, hi)
        X_test  = _winsorize_apply(X_test,  lo, hi)
    scaler = bundle["scaler"]
    return (scaler.transform(X_train),
            scaler.transform(X_val),
            scaler.transform(X_test))
```

`export_input_template.py` uses the same pattern on a single row.

## Section 7 — What the MLP Does NOT Receive

Several fields in the `Position` JSON are deliberately excluded:

- **`tradeType`** — a human-readable label (`"LONG BREAKTHROUGH"` etc.). Not a feature.
- **`exitContext`** — the `DowContext` snapshot at trade exit. Including it
  would leak the future into training.
- **Unclosed positions** — rows where `pnl == 0.0 AND sellDate == ""` are
  filtered by [`load_positions`](neural_network.py#L260-L298). Their P&L is
  unknown, so they have no valid label.
- **`numShares`, `originalStopLoss`, `purchasePrice`, `sellPrice`** — these
  are used during extraction (as normalization anchors) but never appear in
  the feature vector itself.

Within the exported template
[output/data_ingestion_template.json](../output/data_ingestion_template.json),
the following fields exist purely for human readability and are **not** part
of the MLP input:

- All of `metadata` (source position info, pipeline configuration)
- All of `transformation_parameters` (the `winsor_lo/hi`, `scaler_mean/std` arrays)
- `mlp_input.tensor_shape`, `mlp_input.tensor_dtype`, `mlp_input._README`
- For every entry in `mlp_input.values`: `_not_ingested_by_mlp`, `index`,
  `name`, `raw`, `winsorized`

The MLP ingests **only** the `value` field of each entry — equivalently, the
`mlp_input.flat_vector` array — as a flat `float32` tensor of length 77.
