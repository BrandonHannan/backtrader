# BackTrader — Claude Code Guide

## Project Overview

C++ algorithmic trading backtester with Python data acquisition and analysis utilities. The engine runs parametric sweeps across a universe of commodity futures to optimize strategy parameters.

**Language mix:** C++20 (trading engine) + Python (data download & result analysis)
**Build system:** GNU Make + g++ (MinGW on Windows)
**Target platform:** Windows (MSYS2/MinGW)

## Build & Run

### 1. Download data (optional — data.txt may already exist)
```bash
python DownloadDataPython/DownloadData.py
```

### 2. Build and run the backtest
```bash
cd BackTrader
make        # compiles all .cpp files recursively → produces a.exe
make run    # compiles + runs
make clean  # removes a.exe
```

### 3. Analyze results
```bash
python StatisticsPython/Stats.py
```
Outputs `strategy_lookback_optimization_results.csv`.
`Stats.py` reads `output/configuration.json` (written by the C++ engine) to set `INITIAL_CAPITAL` as `valid_stock_count × DowBaseCase.balance`. Falls back to `68000.0` if the file is missing.

### 4. Run the neural network grid search (optional)
```bash
py -3.13 -m pip install -r NeuralNetwork/requirements.txt
py -3.13 NeuralNetwork/neural_network.py          # full 51-config sweep
py -3.13 NeuralNetwork/neural_network.py --fast   # quick 50-epoch sweep for iteration
# Override data path: py -3.13 NeuralNetwork/neural_network.py --data path/to/data.json
```
> **Note:** Use `py -3.13` — the bare `python` command resolves to the MSYS2 build Python which has no packages.
Reads `output/data.json`, runs 51 hyperparameter configurations across Funnel/Diamond/Cylinder architectures, prints a ranked leaderboard (top 10 overall + top 5 per family), and writes `NeuralNetwork/scaler.pkl`, `NeuralNetwork/model.pt`, and `NeuralNetwork/model_metadata.json`.

## Architecture Rules

### Polymorphic strategy components
All three strategy pillars use abstract base classes with `unique_ptr` ownership:

```cpp
// Signal logic
unique_ptr<BaseContext> context = make_unique<DowContext>(...);

// Position sizing / risk
unique_ptr<BasePositionSize> sizer = make_unique<ATRPositionSize>(...);

// Strategy execution
CustomStrategy strategy(balance, move(sizer), move(context));
```

**Adding a new context/sizer/strategy:** always inherit from the corresponding `Base*` class and override its pure virtual methods. Never modify `CustomStrategy` or `BaseStrategy` directly for strategy-specific logic.

### Sweep engine
- `StrategyRunner<T>` — 1D parameter sweep over a `vector<T>`
- `StrategyRunner2D<T1, T2>` — 2D sweep over two parameter arrays
- All sweeps are orchestrated in `StrategyRunner/DowATRStrategy/DowATRStrategy.h` via `ExecuteAllSweeps()`
- New sweeps are added there, not in `Main.cpp`

### Where new code belongs
| What you're adding | Where it goes |
|---|---|
| New indicator | `BackTrader/Indicators/NewIndicator/` |
| New signal logic | `BackTrader/TradingContext/NewContext/` inheriting `BaseContext` |
| New position sizing | `BackTrader/PositionSizing/NewSizer/` inheriting `BasePositionSize` |
| New data structure | `BackTrader/Objects/NewObject/` |
| New utility function | `BackTrader/Functions/NewHelper/` |
| New parameter sweep | `BackTrader/StrategyRunner/DowATRStrategy/DowATRStrategy.h` |

## Critical Notes

### Ticker-isolated execution model (M5)

Each ticker runs as an **independent** paper account using `DowBaseCase.balance` (default `$1,000`). The balance is reset between tickers via `setBalance(initialBalance)` in `StrategyRunner`. This means:

- Risk-per-trade is always `riskAmount × DowBaseCase.balance`, independent of how many tickers are active simultaneously.
- `Total P&L:` printed after the sweep is the **sum of independent $1,000 paper runs**, not a single unified portfolio.
- To convert to a realistic portfolio deployment, scale by `realCapital / (numTickers × DowBaseCase.balance)`.
- **Balance scaling for high-contractSize instruments:** With `contractSize=100` (crude oil, natural gas, copper), the sizer requires at least `(ATR × contractSize / riskAmount)` in balance to produce 1 contract. At `ATR=$2`, `contractSize=100`, `riskAmount=0.02`: minimum balance = `$2 × 100 / 0.02 = $10,000`. Tickers that cannot produce ≥1 contract are silently skipped. Increase `DowBaseCase.balance` in [BackTrader/StrategyRunner/DowATRStrategy/DowATRBaseCase.h](BackTrader/StrategyRunner/DowATRStrategy/DowATRBaseCase.h) accordingly.

### Friction model (C2)

Round-trip costs (commission + spread) are deducted at every position close in `CustomStrategy.cpp`. Values are read from `FrictionPerRoundTrip:` sections in `data.txt` / Dukascopy data files, sourced from `DownloadDataPython/DukascopyTickers.json`. Tickers without an explicit value default to **$0.0** (no friction). Tune the `frictionPerRoundTrip` field in `DukascopyTickers.json` before interpreting sweep results.

### Makefile typo
- [BackTrader/Makefile:5](BackTrader/Makefile#L5): `-I./inlcude` is misspelled (should be `-I./include`). This works because the nlohmann headers are included via relative paths from source files, but the flag itself is wrong.

## Data Flow

```
DownloadData.py
    → data.txt  (OHLCV for 32 commodity futures tickers)
    → DataReader::ReadData()
    → unordered_map<string, StockData>
    → ExecuteAllSweeps(data)              ← DowATRStrategy.h
        → StrategyRunner<T>::run()        ← per parameter value
            → CustomStrategy::ExecuteStrategy() per ticker
                → BaseContext::updateContext() + shouldExecuteTrade()
                → BasePositionSize::purchasePosition()
                → Position written with full DowContext snapshot (entryContext/exitContext)
    → Returns.txt                         ← aggregate P&L for Stats.py
    → output/data.json                    ← individual Position objects for NeuralNetwork
    → output/configuration.json           ← { "initial_balance": valid_stocks × DowBaseCase.balance }
    → Stats.py                            ← reads configuration.json to set INITIAL_CAPITAL
    → strategy_lookback_optimization_results.csv

output/data.json
    → neural_network.py (orchestrator)
        → load_positions()               ← extract 64 features per trade
        → StandardScaler normalisation   ← fit on train split only
        → pos_weight correction          ← num_loss / num_profit ≈ 1.49
        → 51 configs × GenericMLP        ← Funnel (17) + Diamond (17) + Cylinder (17)
            → train_model()              ← Adam + BCEWithLogitsLoss + ReduceLROnPlateau
            → evaluate()                 ← Accuracy, Precision, Recall, F1, AUC-ROC
        → leaderboard (top 10 + top 5 per family)
    → NeuralNetwork/model.pt             ← best model weights
    → NeuralNetwork/model_metadata.json  ← winning config details
    → NeuralNetwork/scaler.pkl           ← scaler for inference
```

## NeuralNetwork

**Purpose:** Binary classifier that predicts whether a trade will be profitable (`pnl > 0`) from the DowContext snapshot captured at trade entry. `neural_network.py` is an orchestrator that runs a 51-configuration hyperparameter grid search across three architecture families and saves the best-performing model.

**How it connects to the C++ backtester:** The C++ engine (`ExecuteAllSweeps`) serialises every closed `Position` object — including the full `DowContext` snapshot at entry — to `output/data.json`. The neural network reads this file directly. No manual data transformation is needed between the two systems.

**Input:** `output/data.json` — array of closed `Position` objects written by `ExecuteAllSweeps()`.

**Feature vector (33 values per trade — ATR/return-normalized for cross-ticker stationarity, all continuous except `positionType`):**

| Group | Count | Fields |
|---|---|---|
| Position-level | 1 | `positionType` (LONG=1/SHORT=0) |
| Price statistics | 6 | (mean,std,min,max - purchasePrice)/atr, **price_cov = std/mean**, **price_t = slope/slopeSE** |
| Volume statistics | 5 | log1p(mean), **max/mean**, **min/mean**, **vol_cov = std/mean**, **vol_t = slope/slopeSE** |
| MACD | 2 | macd/atr, signal/atr |
| Trend | 3 | duration_days (e1→purchaseDate), range_atr ((max-min close)/atr across extrema), extrema_count |
| TrendLine | 4 | slope/mean, (intercept-purchasePrice)/atr, dateDifference, **trendline_distance_atr** |
| DoubleTrend | 3 | same shape as Trend, anchored to its own e1.date |
| DoubleTrendLine | 4 | same shape as TrendLine |
| RSI | 2 | rsi, doubleRsi (RSI is in [0, 100], left untransformed) |
| ATR | 3 | atr/purchasePrice, doubleAtr/purchasePrice, **volatility_ratio = atr/doubleAtr** |

Stationarity transforms applied in [neural_network.py:`extract_context_features`](NeuralNetwork/neural_network.py): all raw prices are converted to ATR-normalized distances from `purchasePrice`; the trend block is summarised into duration / peak-to-trough range / extremum count instead of per-extremum coordinates (zero-padding missing positions is MLP-hostile); raw volumes use a `log1p` baseline plus `max/mean` and `min/mean` spike ratios; slope significance collapses into a single t-statistic `slope/slopeSE`; MACD is ATR-normalized so it shares scale with every other price-distance feature. All `*Ready`, `isActive`, `isTrough`, and `slopeSignificant` boolean flags have been removed (rigid 0/1 channels waste MLP capacity). `tradeType` and `exitContext` are excluded — the former is a human-readable label, the latter would be data leakage.

**Class imbalance handling:** The dataset has ~40% profitable / ~60% loss trades. `BCEWithLogitsLoss(pos_weight = num_loss / num_profit ≈ 1.49)` corrects for this by penalising missed profitable trades proportionally. The original `BCELoss` without weighting caused Recall ≈ 0.006 and AUC-ROC ≈ 0.49 (near-random).

**Normalisation:** Configurable scaler via `--scaler {standard,robust}` (default `standard`) plus `--winsorize <pct>` (default 1.0 = clip each feature to [1%, 99%] of train distribution). Both fit only on the training split. The saved [NeuralNetwork/scaler.pkl](NeuralNetwork/scaler.pkl) is a bundle `{scaler, winsor_lo, winsor_hi, scaler_kind, winsorize_pct}` so inference replays both steps deterministically.

**Feature diagnostics:** [NeuralNetwork/feature_diagnostics.py](NeuralNetwork/feature_diagnostics.py) loads the trained model + scaler bundle and writes `NeuralNetwork/feature_report.txt` with: (a) Pearson correlation pairs at |r| ≥ 0.95, (b) permutation importance ranked by AUC-ROC drop, (c) drop candidates (features whose shuffling does not hurt AUC).

**Architecture families (51 configs total):**

| Family | Shape | Configs | Hidden layer pattern |
|---|---|---|---|
| Funnel | `architectures/funnel/funnel.py` | 17 | Monotonically narrowing: 1024→512→256 down to 128→64 |
| Diamond | `architectures/diamond/diamond.py` | 17 | Compress → expand → compress: bottlenecks 8–64, peaks 64–256 |
| Cylinder | `architectures/cylinder/cylinder.py` | 17 | Constant width: 32–512 wide, 1–5 layers deep |

All use `GenericMLP` from `architectures/base.py` — a shape-agnostic MLP with:
```
For each hidden layer: Linear → BatchNorm1d → ReLU → Dropout
Output layer:          Linear(→ 1)   [raw logit, no Sigmoid]
```
Loss: `BCEWithLogitsLoss(pos_weight)` | Optimizer: Adam | LR scheduler: `ReduceLROnPlateau(patience=5, factor=0.5)` | Early stopping: patience=15

**Training split:** 70% train / 15% val / 15% test — stratified to preserve class balance.

**Outputs:**
- `NeuralNetwork/scaler.pkl` — bundle: fitted scaler + winsorize bounds + scaler_kind
- `NeuralNetwork/model.pt` — PyTorch state dict of the best model
- `NeuralNetwork/model_metadata.json` — family, config name, hidden_dims, dropout, and test metrics of the winner
- `NeuralNetwork/feature_report.txt` — generated by `feature_diagnostics.py` (correlations + permutation importance)
- Printed leaderboard: top 10 overall + top 5 per architecture family (sorted by AUC-ROC, F1 as tiebreaker)

**Where architecture documentation lives:**
- `NeuralNetwork/architectures/funnel/ARCHITECTURE.md` — funnel design, math, worked numeric trace, backprop
- `NeuralNetwork/architectures/diamond/ARCHITECTURE.md` — diamond design, bottleneck rationale, backprop with pos_weight
- `NeuralNetwork/architectures/cylinder/ARCHITECTURE.md` — cylinder design, constant-width gradient flow advantage, backprop
